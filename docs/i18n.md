# Internationalisation

Three languages: **Spanish (`es`, default)**, English (`en`), Portuguese (`pt`).

There are two independent language settings. Knowing which one a screen uses explains most
"why is this in Spanish?" questions.

| | Site language | Editor language |
| :--- | :--- | :--- |
| Applies to | Landing, pricing, header, dashboard, sign-in | Everything inside `CVBuilder`, plus the generated CV's headings and dates |
| Decided by | URL prefix (`/`, `/en`, `/pt`) | `localStorage['app-lang']` |
| Changed with | `LanguagePicker` in the header | Flag toggle in the editor toolbar |
| Remembered in | Cookie `cvstudio_locale` | `localStorage` |
| Read through | `lang` prop, `getLangFromUrl()` | `useTranslation()` |

They are not synchronised: `/en/app/editor` shows whatever language the editor toggle was last set
to.

## String catalogue (`src/i18n/locales.ts`)

One object, `locales = { es, en, pt }`. Each language has the same shape:

```
ui        site chrome
  nav · hero · features · pricing (plans, table) · footer
header    editor toolbar and banners
sections  form section titles
labels    form field labels
actions   buttons and confirmations
ai        AI menu, alerts, ats, coverLetter
```

`export type Translation = typeof locales.es` — Spanish is the reference shape. A key missing from
`en` or `pt` is a type error wherever `t` is typed as `Translation`.

## Three ways strings are read

1. **`useTranslation()`** (`src/hooks/useTranslation.ts`) — editor. Returns `{ t, lang, toggleLang,
   setLang }`; `t` is the whole language object, used as `t.actions.save`. Passed down as a prop.
2. **`useUiTranslations(lang)`** (`src/i18n/utils.ts`) — `.astro` pages and a few components.
   Returns `t('dot.path')` scoped to the `ui` subtree, falling back to Spanish, then to the key
   itself. Can return an object (`t('hero')`), which callers cast.
3. **Direct indexing** — `locales[lang]?.ui.nav || locales.es.ui.nav` in `SiteHeader`, `UserMenu`,
   `HeroActions`, `FeaturesSection`, `Dashboard`.

## Hardcoded strings

Not everything is in the catalogue. Inline `lang === 'es' ? … : …` ternaries or plain literals
exist in `Dashboard`, `GuestBanner`, `AIChoiceModal`, `AuthRequiredModal`, `PricingSection`, toasts
in `useCVLogic`, and several are Spanish- or English-only (`CookieConsent`, `privacy.astro`,
"Cargando...", "Actualizando vista previa...", the PDF download `alert`). `<html lang>` is always
`es`.

## Routing

- `astro.config.mjs` declares `i18n: { defaultLocale: 'es', locales: ['es','en','pt'],
  routing: { prefixDefaultLocale: false } }`.
- Prefixed pages are real files under `src/pages/[lang]/` that mirror the Spanish ones. Each
  validates `lang` and redirects to `/404` if it is not `en` or `pt`.
- `src/middleware.ts` redirects un-prefixed URLs to the visitor's preferred locale
  (cookie → `Accept-Language` → `es`). It never redirects *away* from a prefix.
- `LanguagePicker` writes the cookie and navigates to the equivalent path in the new locale.
- Components build links with `const langPrefix = lang === 'es' ? '' : \`/${lang}\``.

## Language of the CV itself

`generateMarkdown(cvData, lang)` receives the **editor** language, so toggling it re-titles the
sections ("Experiencia Profesional" ↔ "Professional Experience") and reformats dates. It does not
translate content — that is the AI **Translate** action. The stored `language` field
(`'ES' | 'EN' | 'PT'`) labels the CV in the dashboard.

## Adding a string

1. Add the key under the right subtree in `es`, then the same key in `en` and `pt`.
2. Use it via `t.…` (editor) or `t('…')` (site).

## Adding a language

1. Add a full block to `locales.ts`.
2. Add it to `locales` in `astro.config.mjs`.
3. `src/middleware.ts`: the `locales` / `prefixedLocales` arrays and every pattern in
   `isPublicRoute`.
4. The `['en','pt']` guards in `src/pages/[lang]/*.astro`.
5. `LanguagePicker` (`languages` list and its prefix check).
6. `useTranslation` (`toggleLang` cycle and the union type) and the `'es' | 'en' | 'pt'` unions
   across the editor.
7. `titlesMap` in **both** `markdownGenerator.ts` and `markdownParser.ts`, plus the parser's
   month-name table and the `Languages`/`Interests` regexes.
